## 1. 目标与范围

本轮目标是交付一个范围明确、能重复验证的 Windows 规则格网版本。用户能安装后完成 OSGB 转换、顶层重建、成果预览、取消任务；重启后能恢复任务记录并将未完成任务标记为中断。这里不表示已经支持继续计算或断点续跑。设置必须确实生效；损坏数据明确失败；正式安装包使用的二进制与验收使用的二进制一致。

本轮保持 Tauri + React + Cesium、独立 Rust Processor、预构建 Converter、Rust TopRebuild 的架构。默认使用保留原纹理和 1 个转换 worker。KTX2 继续按实验能力单独验收，不能用纹理实验阻塞已经通过的 keep 路径，也不能将失败的实验写成通过。

初始支持声明维持 Windows、连续规则网格、≤16×16 的既有范围。该数字是当前产品与验收范围，不是证明所有此规模数据都兼容。稀疏网格、任意城区、50 GB 以上与百平方公里能力都不在本轮承诺内。

不开展：UI 全面重做、Qt/OSGB 原生预览、转换器整体重写、atlas、remesh、强制 weld、implicit tiling、分布式、断点续跑、自动覆盖既有成果。

### R00 — 建立本轮基线与证据目录（P0）

**工作：**

1. 开始执行时重新 fetch，记录 master、开发分支、共同祖先；若远端变化，先更新差异表。
2. 从最新 master 建立 `codex/v1-convergence` 或按主题建立小分支；保留原分支。
3. 记录 Rust/Node/Windows/WebView2 版本、CPU、内存、磁盘、Git SHA、Converter/Processor/TopRebuild/BasisU hash。
4. 创建本轮状态表，使用“未开始、进行中、代码通过、验收通过、受阻”区分状态。
5. 验收产物放在忽略目录 `acceptance-results/v1-convergence/<run-id>/`；仓库只提交精简报告、脚本和小夹具。

**交付物：** 基线 JSON、分支差异清单、任务状态表、复跑命令。

**验收：** 任意结果都能追溯到源码 SHA、runtime hash、输入数据与参数；不混用不同版本的结果。

### R01 — 修复并发参数传递和重试语义（P0）

**代码范围：** `crates/processor/src/stages/convert.rs`，相关受控子进程测试。

**工作：**

1. 统一解释 `options.convert.threads`：缺省、0/自动、1、2、4；其他 API 输入明确校验。
2. 建议契约：任务中显式数值优先；显式 0 表示 converter 自动；任务未指定时才读取开发环境变量；无覆盖则使用 converter 默认。
3. 首次调用必须把解析后的设置实际传给子进程。显式自动要避免继承环境变量后意外变成固定线程数。
4. 分开记录请求设置、实际传入的覆盖值、converter 实际 worker 数；日志无证据时不能声称已经使用某个线程数。
5. 保留已知原生崩溃/空 JSON 场景的一次单线程重试；真正单线程失败不再重复；取消后不重试；重试前只清理本任务拥有的转换子目录。
6. 正常业务失败不得一概重试，避免掩盖损坏数据、权限、路径或参数问题。

**测试：** 用受控假 converter 记录实际收到的环境变量，覆盖 1/2/4/自动/缺省/环境覆盖/非法值；模拟目标崩溃、普通错误、取消，验证调用次数和重试参数。

**验收：** UI 选择 1 时，第一次转换确实收到单线程参数；配置与日志一致；目标故障最多重试一次；取消没有额外启动。

### R02 — 设置持久化、旧配置兼容与默认值（P0）

**代码范围：** `settings_store.rs`、前后端设置类型、`Settings.tsx`、`OsgbConvert.tsx`、`ProcessTiles.tsx`。

**工作：**

1. Rust `AppSettings` 增加与前端一致的默认并发字段，数据库 JSON 能完整读写。
2. 旧 JSON 缺字段时使用兼容默认值；不能因为新增字段使旧安装启动或打开设置失败。
3. 新安装默认并发为 1、默认纹理为 keep；检查首次加载设置后是否覆盖页面默认值。
4. 尊重用户已有显式设置；不要无提示把历史自选压缩设置改掉。缺字段与显式值分别处理。
5. 前后端校验范围一致；设置页保存、退出重启、转换页采用设置形成完整链路。
6. 运行时缺少 KTX2 组件时，明确不可用及原因；不把实验功能自动打开。

**测试：** SQLite round-trip、旧 JSON、显式 keep/KTX2、非法线程数、首次启动、保存后重启。

**验收：** 设置保存不会丢字段；重启后并发仍正确；新安装无需改设置即可执行 keep + 1 worker。

### R04 — 顶层重建正确性与原始细节保留（P0）

**代码范围：** `adapter.rs`、`selector.rs`、`types.rs`、`tileset_writer.rs`、`b3dm.rs`、对应 integration tests。

**工作：**

1. 正式路径缺失/损坏内容必须失败；合成几何只允许显式测试夹具使用。
2. 验证 Representation frontier 覆盖每条有效子分支，不能以单个可见节点代替完整覆盖。
3. 保留原始 Block 外部 tileset 及其细节子树；记录复制映射、内容数量和 hash 差异。
4. 检查嵌套 transform、旋转 box、非零索引、ECEF 大坐标、parent-local 转换以及 world transform 不变性。
5. 核实 B3DM feature/batch table、GLB payload 与填充的对齐方式；用外部校验结果定位问题，不以“本地能读”作为唯一证据。
6. 检查 geometricError 单调性、覆盖范围和 REPLACE 切换；层级数量按真实索引计算，不能把非零起点的 4×4 一律要求为 16→4→1。

**测试：** 2×2、4×4、16×16；奇数边界、负索引、缺块、缺 content、坏 B3DM、嵌套 external tileset、变换与旋转 BV、KTX2 输入。

**验收：** 无合成成功冒充真实处理；原始细节完整；坐标不漂移；全部有效子分支有覆盖；损坏或不支持输入返回可定位的错误。

### R05 — 内部校验与外部标准校验（P0）

**工作：**

1. 比较主线 `stages/validate.rs` 与开发分支 `validator.rs`，形成规则对照，收敛一个正式入口。
2. 内部 Layer A 在 commit 前检查结构、有限数值、BV、GE、相对 URI、内容存在性、B3DM/GLB 长度与头、外部引用循环、路径越界和 required extensions。
3. 保持可取消、遍历有界、报错有完整路径；校验报告不应无限写入 UI 日志。
4. 固定 Layer B 校验工具版本，保存原始报告、命令、退出码和错误数量。
5. 对同一 PlanD 输入分别校验 convert-only 与 rebuild 成果，重新确认历史 16 个错误的当前数量、类型和产生阶段。
6. 将问题分成 converter 产物、rebuild 新引入、明确不支持输入、工具兼容问题；能修复的产物问题必须修复。不直接屏蔽错误或删除失败项。
7. 真正的工具误报需最小复现、版本与理由；无法关闭时保持该数据族不在已验收范围内。

**交付物：** 内部报告、外部报告、失败类型表、最小复现和回归夹具。

**验收：** 正式声明支持的样本 Layer A 通过且 Layer B `numErrors=0`；任何失败阻止该次任务提交/对应数据族发布声明。Layer B 可以是 CI/验收工具，无须强塞进每次桌面处理。

### R06 — 输出提交、取消与故障恢复（P0）

**工作：**

1. 保留输出存在即拒绝、临时目录独占创建、marker 归属检查、同卷 no-replace rename。
2. 明确失败保留诊断、取消清理本任务临时目录、已提交成功不被迟到取消改写的语义。
3. 验证崩溃窗口：转换中、重建中、校验中、提交前、提交后但数据库登记前。
4. 最终目录已提交而登记失败时可识别、重新登记，不重复转换，不删除已成功成果。
5. 测试同时提交相同输出、marker 不匹配、软链接/junction、权限拒绝、磁盘不足。
6. 故障注入只在隔离测试目录、限额磁盘或 VM 中执行，不能填满或改变用户系统盘权限。

**验收：** 输入和既有成果 hash 不变；失败不出现伪成功成果；取消没有残留进程；重启后活动任务变 interrupted 且清除失效 PID。

### R07 — KTX2 与安装运行时依赖（P1）

**工作：**

1. 决定正式纹理实现：保留封装 sidecar 或采用开发分支 Rust 实现，依据格式覆盖、错误语义、Windows 打包和真实回归结果。
2. 矩阵覆盖 OSGB→ETC1S、OSGB→UASTC、已有 Tiles→KTX2、已有 KTX2→重建、重建→KTX2。
3. 核实不透明 KTX2 透传的适用条件：确需 resize/重编码时不能假装已满足预算；报告实际跳过操作和保留字节数。
4. 每条路径检查扩展声明、纹理来源、透明度、材质关联、Cesium 显示和纹理体积。
5. 安装模式仅使用随包组件；不得依赖源码目录或系统 Python。封装工具内部带运行时可接受，用户无须安装 Python；开发验收脚本使用 Python 不算产品依赖。
6. 验证 basisu 的 CRT/zstd 依赖以及 x64 架构；不能仅因找到同名 DLL 就算打包正确。
7. 包含缺工具、缺 DLL、工具崩溃、编码失败、取消的负向场景。

**验收：** 宣称可用的每个组合都有安装环境证据；失败不提交；未通过组合保持实验/不可用并写出具体范围。

### R08 — 同一版本真实数据与空间质量（P0）

**数据梯度：**

| 级别 | 数据 | 目的 |
| --- | --- | --- |
| D0 | 测试生成的有效 tiny B3DM/GLB | 快速正确性和故障回归 |
| D1 | OSGBny 小样、中文路径副本 | 转换、诊断；稀疏重建应明确拒绝 |
| D2 | LandsD 连续 4×4 或已有 5×4 | 规则数据标准验收 |
| D3 | PlanD 连续 4×4 | 不同来源、Layer B 缺口定位 |
| D4 | 同来源 8×8 | 资源、取消、全链路稳定性 |
| D5 | 同来源 16×16 | 当前范围上界验收 |

**执行：**

1. 优先复用可核实的已有数据；记录来源、下载时间、网格、数量、大小、metadata 与清单 hash。
2. 不混用 LandsD 和 PlanD 结果；每个样本独立生成 baseline 与 candidate。
3. 小样通过后才跑大样；大数据前估算输入、两套输出、临时目录及报告空间。
4. 每次记录 stage 时间、峰值内存（不可用则标缺）、临时磁盘峰值、输出体积、内容/proxy 数、层级、warnings。
5. 对比原始细节、重建近景、重建远景：定位、完整性、纹理、缝隙、切换和覆盖。
6. gap 必须比较同一边界的 baseline 与 candidate，区分原始缺口、简化新增缺口、测量方法误差；不把数百米 warning 简单归为无害。
7. 选定小样重复 10 次检查稳定性；大样成功跑一轮后仅在有关改动时复测，避免无意义重复。

**验收：** 各数据族有明确支持/拒绝结果；支持样本校验通过，无新增整块消失或坐标偏移；质量告警有解释和处理结论。

### R09 — Cesium A/B、LOD 与性能（P1）

**工作：**

1. 迁入并审查 A/B harness；同数据、同 runtime、同 Cesium、同视口、同 camera、同 SSE 和缓存策略。
2. 分别跑 far/mid/near，SSE=8/16/32；冷缓存与热缓存分开，不能交叉比较。
3. 固定等待定义：资源请求完成、加载队列、画面稳定；超时报告 timeout，不能使用提前采样时间当完整概览时间。
4. 记录 content 请求、实际传输字节、概览时间、选中层级、加载错误、截图；frame/FPS 仅在可靠采样时报告。
5. 建议每个主要配置重复 3 次，以中位数报告，并保留原始样本和波动范围。
6. 复核近景 timeout 和流量上升；判断是缓存/测试窗口、预取、proxy 开销、树结构还是实际错误。
7. 先检查 proxy 是否按预期被选中，再调 GE/预算；禁止仅调 SSE 让数字好看而忽略细节质量。

**沿用开发分支远景门槛：** 请求减少 ≥50%、下载字节减少 ≥40%、首次完整概览时间改善 ≥25%，三项满足至少两项。三项原始结果均展示。

开发分支历史结果已满足该复合门槛。不能因为时间项只改善 6.1% 就改称远景测试失败，也不能据此宣称近景更快。软件渲染与真实 GPU 结果分别标明。

**验收：** 合并后目标样本满足远景复合门槛；中近景没有未解释缺块/加载错误；SSE 扫描与近景 timeout 均有结论；性能收益不能抵消空间质量失败。

### R10 — 固定 converter 发布与可复现安装包（P0）

**工作：**

1. 在 converter 仓库确认待发布修复对应源码 SHA、构建配置、DLL/OSG/GDAL/PROJ 清单和许可证。
2. 候选 zip 完成 `--help`、有效小样、坏输入、中文路径、线程控制验证；记录 SHA256。
3. 准备版本化 converter Release 与主仓库清单更新；发布动作按仓库实际授权流程执行，先形成可审阅候选。
4. 正式包只使用固定 URL + SHA256，重新构建时不使用本地 `-ConverterZip` 覆盖。
5. 校验 CRT DLL 的架构和来源；SysWOW64 不得被当作 x64 DLL 的无条件后备。
6. 生成 runtime 文件 manifest，检查 converter/bin/texture 所有依赖；确认桌面默认设置和最新前端构建进入安装包。
7. 在 CI 生成 NSIS，记录安装器 hash、构建日志、runtime hash、工具版本。

**验收：** 新环境能从固定清单构建；安装内二进制与 manifest 匹配；依赖缺失在打包时失败；候选 zip、旧固定包、正式发布包不混称。

### R11 — 干净 Windows 安装 GUI 全流程（P0）

**环境：** Windows x64 VM/独立测试机；无 Git/Rust/Node/Python/vcpkg、源码目录及 `GEOFORGE_*` 覆盖；不预装全局 VC++ 运行库。WebView2 的预装或安装下载条件必须记录。

**场景：**

1. 安装、首次启动、capabilities 检测；普通用户可写入自己的应用数据。
2. 中文用户名/中文输入路径/带空格安装路径；先小样转换 keep，再重建，再 Cesium WebView 预览。
3. 设置默认并发、保存并重启，确认 UI、任务 JSON、converter 实际行为一致。
4. 已有 Tiles 后处理；缺元数据、坏文件、不支持网格、输出已存在等明确报错。
5. queued 取消、running 取消；有活动任务时点窗口关闭；检查子孙进程退出并重启查看 interrupted。
6. 历史、日志、成果保留；提交成功后登记失败的恢复流程。
7. 在隔离容量/权限环境检查写入失败和错误信息；保留输入与旧成果。
8. KTX2 按 R07 通过组合执行；断网条件下使用本地 Cesium 和成果预览。
9. 升级/重装时旧设置、任务和成果不丢；卸载数据保留策略明确。

**交付物：** OS/WebView2 版本、安装器 hash、截图/录像、任务 ID、数据库状态、日志、进程检查和通过/失败表。

**验收：** 上述核心 keep 流程通过；无开发机依赖；无输入破坏、静默失败、错误成功或残留进程。CLI/单测结果不能替代窗口操作证据。

## 8. 风险、处理方式与停止条件

| 风险 | 处理 |
| --- | --- |
| 开发分支覆盖主线加固 | 三方比较、分主题迁入、运行关闭/取消/打包回归 |
| 旧 runtime 不含候选修复 | 用 hash 分清版本，最终验收重跑固定包 |

| 磁盘/下载成本过高 | 先小后大、运行前预算，不盲目下载更大样本 |

## 11. 后续重点：可靠并发、处理速度、暂停与续跑

> 后续方向已独立整理至 [07-concurrency-performance-resume-plan.md](./07-concurrency-performance-resume-plan.md)。本节保留早期讨论，后续并发、性能、暂停续跑规划以新文档为准。

补充日期：2026-09-21。根据用户反馈，将并发可靠性和吞吐量列为首要后续方向；暂停与恢复作为明确的新能力规划。R01 参数修复仍立即优先；并发故障复现也应尽早开始，不必等待全部安装验收完成。

### 11.1 当前能力与限制

- Desktop 目前一次执行一个任务；转换器内部可按 Tile 并行。这是两个不同层次的并发。
- 主线会对特定空 JSON/原生崩溃清理本次转换输出并单线程重试。重试是稳定性措施，不是并发问题已修复，也可能增加总耗时。
- 当前 Processor 控制协议仅有取消，没有暂停/继续命令；桌面关闭与启动恢复把未完成任务标为 interrupted。
- 当前没有可验证的任务检查点，不能从历史记录恢复已完成的 Tile 工作；普通失败保留临时文件也不等于可安全续跑。
- 本地相邻 converter 源码显示 Rayon worker 并行进入 C++ 转换入口；这只是排查入口，尚未证明是哪项原生共享状态、库调用或数据触发崩溃。本地源码也不能默认等同于当前安装包二进制。

### S01 — 并发故障复现与根因修复（P0，与首批修复衔接）

1. 固定实际使用的 converter 源码 SHA、二进制 hash 和输入；优先复现用户失败样本，无该样本时使用历史触发数据。
2. 先完成 R01，让 1/2/4/8 worker 确实生效；诊断运行分别记录首次失败与自动重试，不能以重试成功掩盖首次失败率。
3. 对相同输入和参数重复运行，记录 Tile、worker、阶段、退出码、stderr、崩溃 dump、内存和线程数量。逐步缩小触发样本。
4. 比较 keep 与压缩路径，检查 C++ 入口、插件初始化、共享缓存、全局对象、编码器重入、写入路径和对象生命周期。它们是待验证假设，不能先入为主认定原因。
5. 用适用工具获取调用栈或内存错误证据；依据根因选择局部同步、每 worker 独立状态、初始化调整或进程隔离，并记录性能代价。
6. 如考虑多进程，先设计互不重叠的 Tile 输出和单一根 tileset 汇总；禁止多个完整 converter 同时写同一个成果目录。

验收：修复前有可重复失败或明确诊断证据；修复后同样本、同参数无该故障；建议 1/2/4/8 worker 每档至少 10 次小样压力运行，大样在候选稳定后验证。该样本通过只证明对应缺陷已关闭，不宣称所有并发输入安全。

### S02 — 分阶段吞吐量优化（P1，依赖可靠并发）

1. 先建立 scan/convert/rebuild/texture/validate/commit 的时间分布，找最慢阶段；分别测 CPU、磁盘、峰值内存、实际线程数和重试开销。
2. 对比 1/2/4/8 worker 的耗时与资源曲线，报告加速比和失败率；不能假设线程翻倍就应当快一倍。
3. 排查外层 Tile 并发与内层压缩线程叠加、磁盘争用、大 Tile 长尾、重复读取/解码/复制等实际瓶颈，优先改证据最充分的一项。
4. 建立 CPU 和内存预算内的 worker 上限、有限在途任务和背压；自动模式同时考虑资源约束，不只看核心数。
5. 单任务稳定提速后再评估多个桌面任务并行；各任务共享资源预算，避免每个任务独占全部核心。
6. 使用同一批代表性数据，分别报告各阶段及端到端改善；小样、冷缓存和热缓存分开。

验收：结果质量不退化、无新增崩溃、内存受控，并有可重复的吞吐收益。具体速度目标在取得基线后制定，不提前承诺倍数；无收益的优化不进入默认路径。

### S03 — 检查点与安全续跑基础（P1，新能力）

1. 先定义可重用工作单位：转换的完整 Tile/Block 子树、重建的依赖已完成 Proxy、纹理的完整文件。首版可先实现转换阶段，其他阶段明确边界。
2. 建立原子完成记录，包含任务/输入指纹、参数、工具版本、坐标设置、输出清单和校验结果；仅文件存在不足以判定完成。
3. 单元写入临时位置，完整校验后再标记完成；处理中崩溃的半成品重新执行，不当作可复用成果。
4. 恢复时验证源数据和参数，依据依赖关系失效下游结果；不兼容的版本拒绝静默复用并说明需要重算的范围。
5. 设计 pause、cancel、failure 的不同保留策略。用户取消和既有清理行为不能被悄悄改成暂停；保留数据要展示位置、大小和清理入口。
6. 阶段级检查点可以先跳过完整已通过阶段，但转换阶段中断仍可能重跑该阶段；Tile 级检查点才减少长转换中的重复工作，UI 必须准确说明。

验收：在工作单元完成前后注入终止，恢复后只复用已验证单元；无缺块、重复挂载或旧参数混入；最终成果通过与全新运行相同的正确性和格式校验，不强制要求非确定编码输出逐字节相同。

### S04 — 用户可见的暂停/继续（P1，依赖 S03）

1. 建议采用协作暂停：收到请求后停止派发新单元，让在途单元到达安全边界并写入检查点，然后报告 paused。
2. UI 增加 pausing、paused、resuming；展示当前进度和暂停等待原因。大单元未完成前不能立刻声称暂停成功。
3. 提供同会话继续，并在检查点支持范围内允许关闭应用后继续；恢复前完成输入、工具和参数兼容检查。
4. 首版可在阶段边界暂停，但必须明确“等待当前阶段完成”；要在转换中细粒度暂停，需要修改 converter 调度与控制协议，仅在 Desktop 增加按钮不够。
5. 全部工作完成后的短提交窗口不接受暂停；暂停期间不发布半成品，不删除可恢复数据。
6. 验证重复暂停、暂停与取消竞争、暂停时退出、恢复时输出路径被占用、磁盘不足、输入已变更和跨版本恢复。

验收：暂停后工作不再持续派发、进度保留、继续后没有重复处理已确认单元；重启后仅在通过兼容检查时续跑；不支持暂停的阶段有准确提示。

不建议把操作系统强行挂起进程作为正式暂停方案：它没有持久检查点，仍占用内存和资源，也不能解决应用退出后的续跑需求。

### 11.2 推荐实施顺序与范围决策

顺序：R01/R02 → S01 并发根因 → S02 吞吐量 → S03 检查点 → S04 暂停/继续。

R04–R06 的正确性、校验和输出保护是优化/续跑共同依赖；这些门槛应在每次算法与调度改动后保持。S01 的故障复现可与主线收敛同步推进；最终安装验收应在纳入本次版本的性能修复之后执行。

建议把可靠单任务并发纳入下一可用版本；多任务并发延后。检查点和暂停涉及 converter、Processor、数据库和 UI 的协同变更，先完成设计与转换阶段试点再排期，不沿用前文 11–20 人日估算，也不表示这些能力已实现。
