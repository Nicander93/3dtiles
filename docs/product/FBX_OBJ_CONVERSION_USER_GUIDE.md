# FBX / OBJ 转 3D Tiles 使用指南

## 支持范围

GeoForge 当前提供 FBX 与 OBJ 的桌面转换入口。处理流程调用项目已有的 `geoforge-converter` 实现，不在主应用中另造模型解析器。成功任务输出单瓦片 3D Tiles 1.0（`tileset.json` 和关联 B3DM）。当前 UI 默认缺失贴图按错误处理：不会把缺图模型伪装成无问题的成功结果。

支持输入的几何、材质和贴图能力受 converter/ufbx 版本及源文件内容影响。转换能读入模型并不代表所有材质着色特性、动画、骨骼或复杂材质网络都能在 3D Tiles 中等价表达；请以输出检查和目标客户端显示结果为准。

## 操作步骤

1. 在“模型转换”中选择 FBX 或 OBJ，并选取模型文件。输入扩展名必须与格式选择一致。
2. 等待输入扫描完成。扫描会检查 OBJ 的 MTL 和可定位的贴图依赖；扫描还未完成或输入/贴图目录发生变化时，提交按钮不可用，待新扫描结果返回后再提交。
3. 设置模型单位和轴向。FBX 可使用文件元数据；OBJ 必须明确选择单位及轴向，因为 OBJ 本身不可靠地声明这些信息。若尺寸明显不对，先核对建模软件导出单位及上/前轴设置。
4. 对 OBJ/FBX 外部贴图，确保贴图与 MTL/模型一起放在可解析位置；若放在其他目录，使用“外部贴图目录”添加每个必要目录。目录变更后等待重新扫描。
5. 选择地理参考方式：本地锚点适合输入已处于局部坐标的模型；投影坐标模式需要正确的源 CRS（如 `EPSG:4547` 或 WKT2）、源轴顺序和 E/N/H 原点偏移。不要仅凭地图位置猜测 CRS 或高度基准。
6. 设置输出位置并启动任务。完成后检查任务日志、`tileset.json`、引用的 B3DM 文件及实际地图位置/尺度。

## OBJ 与 MTL 打包建议

- 一并交付 `.obj`、其 `mtllib` 指定的 `.mtl`，以及 MTL 引用的纹理文件。
- 保持相对目录结构最稳妥；例如模型在 `asset/mesh.obj`、MTL 在 `asset/materials.mtl`、纹理在 `asset/textures/albedo.png` 时，确保 MTL 中相对路径正确。
- 若贴图被集中存放在其他目录，将该目录作为外部贴图根目录添加。根目录应是实际存在的文件夹，而非贴图文件本身。
- 文件名大小写、空格和相对路径应与 MTL 一致。扫描器识别常见 MTL 贴图语句和选项，但 converter 的解码/材质支持是最终权威；扫描成功不能证明图像一定可解码。

## 排错

- **提交按钮不可用：** 检查格式与扩展名是否一致；等待扫描完成；修正扫描报告中的 MTL/纹理缺失；若刚添加/删除贴图目录，等待重新扫描。
- **提示找不到纹理：** 检查 OBJ 的 `mtllib` 路径、MTL 内 `map_Kd` 等贴图路径；确认贴图真实存在；添加包含资源的根目录后重新扫描。
- **模型尺寸错误：** 核对导出单位与 UI 单位。OBJ 没有可信单位元数据，厘米误按米解释会造成 100 倍差异。
- **朝向或位置错误：** 核对轴向、投影 CRS、E/N 轴映射和原点偏移；分别用已知控制点验证水平位置与高度。
- **任务失败：** 查看任务日志中的首个转换错误和 native 插件加载信息。桌面运行需使用带齐 converter 动态库和 OSG 插件的运行时包；仅将 EXE 放入 PATH 不够。
- **任务持续时间异常：** 外部子进程默认有 6 小时上限；管理员可通过 `GEOFORGE_PROCESS_TIMEOUT_SECS` 调整（最大 24 小时）。取消任务仍会终止子进程并清理未提交临时目录。
- **tileset 存在但不能显示：** 检查 tileset 引用文件是否齐全，再确认目标客户端支持输出内容；不要只依据退出码判断成功。

## 已知限制

- 当前转换输出配置固定为单瓦片 3D Tiles 1.0，未提供多层 LOD 调节界面。
- OBJ 的单位和轴向必须由用户提供；FBX 则依赖文件元数据与 converter 对其的解释。
- 外部纹理必须可访问且可解码；扫描支持范围并不覆盖所有 MTL 扩展语法。
- 投影 CRS 与高度基准必须由数据提供方确认；对于垂直基准、复杂坐标操作及高精度工程数据，须使用已知控制点独立验收。
- 发行包启动、动态库/插件完整性和非 Windows 平台支持需要在对应正式发布构建中单独验收；本指南不将本机 CLI smoke 视为发布包验收。
